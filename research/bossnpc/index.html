UnityLLMRAG

具有长期记忆的 LLM Boss 对话研究原型

Unity 回合制游戏研究原型：记录玩家行为并比较三种记忆检索策略，让 Boss 根据真实游玩经历生成可追踪的动态对话

2026.08

项目描述

BossNPC 是一个面向游戏 NPC 长期记忆的研究原型。项目建立在此前制作的 Unity 回合制卡牌战斗原型之上，研究一个具体问题：当 Boss 需要根据玩家过去的真实行为生成对话时，系统应该如何从长期记忆中选出最合适的少量事件交给大语言模型？

玩家首先完成三场小型战斗。系统会记录每回合造成的伤害、手牌使用、战斗持续回合、剩余生命值，以及玩家在战后作出的剧情选择。随后，Boss Rowan 会在三场实验战斗中根据这些经历评价、质问或回应玩家。对话并不是读取预写分支，而是由当前战况、Boss 人设、当前战斗的工作记忆，以及检索出的 Top3 长期记忆共同生成。

回合制卡牌战斗基础：玩家通过卡牌、体力和棋盘位置完成行动。

玩法与记忆形成

项目采用回合制卡牌战斗结构。玩家需要消耗体力使用近战、重击、投枪和范围攻击等卡牌，在棋盘上选择目标并处理不同类型的敌人。回合制节奏也为在线对话请求提供了自然的等待窗口，避免生成延迟打断连续操作。

前三场战斗分别引入与 Rowan 具有忠诚、恩情和亲属关系的角色。每次胜利后，玩家还需要决定如何处置对手。这些战斗不是固定背景文本，而是长期记忆的来源：同一个玩家可能快速取胜并处决敌人，也可能负伤、消耗更多回合并选择宽恕，由此形成不同的 Boss 对话依据。

三场前置战斗会产生战斗表现、最终状态和剧情选择等长期记忆。

系统将对话信息分为三层：

  • Static Context：世界设定、Rowan 的性格、价值观和人物关系，始终进入提示词。
  • Long-term Episodic Memory：来自前三场战斗的长期情节记忆，由检索器选出 Top3。
  • Working Memory：当前 Boss 战中的即时事件，例如率先击败支援单位；直接进入提示词，并在重试战斗时清空。

对话生成与本地代理

Boss Rowan 在战斗过程中引用玩家此前的行为生成动态台词。

项目配套了一个本地 Node.js 服务 LLMProxy：

  • /embed 在本地计算记忆与查询的向量，玩家数据无需为相似度计算离开设备。
  • /dialogue 将生成请求转发至 OpenAI-compatible 接口，并把 API 凭据隔离在 Unity 构建之外。
  • 正式实验中的对话生成与模型辅助评分统一使用 DeepSeek-V4-Pro-0813，确保参与者和检索条件之间的模型配置不变。
  • 发布包附带 Windows x64 Node.js 运行时、锁定依赖和 ONNX 嵌入模型，降低参与者的安装成本。

主要实现

  • 使用 Unity 2022.3.62f2 / C# 完成回合制卡牌战斗、棋盘移动、敌人 AI、场景流程与中英文本地化
  • 将玩家的回合行为、战斗结果和叙事选择转换为原子化、结构化的长期记忆
  • 实现跨场景 MemorySystem、当前战斗 Working Memory，以及向量与重要性缓存
  • 通过统一接口实现 Similarity-only、Rule-based Importance、Model-assisted Importance 和 Full Memory 检索器
  • 实现基于战斗状态的对话触发、请求冷却、优先级、取消、验证、重试与失败回退
  • 搭建本地 Node.js 代理，集成本地 ONNX embedding 与远程 OpenAI-compatible 对话接口
  • 实现 Scripted、Full Memory 和 Experiment 三种运行模式，以及独立场景调试配置
  • 实现 A/B/C 实验顺序、匿名 SessionCode、问卷衔接与 JSONL 全链路日志
  • 制作离线检索基准工具，对 144 个查询—记忆组合计算 Precision@3、Recall@3 和 nDCG@3

成长 & 反思 & 未来

这个项目让我把游戏开发、LLM 工程和用户研究连接成了一条可运行、可验证的完整链路。相比只展示一段生成效果，我更关注生成结果之前发生了什么：游戏记录了哪些事实、检索器为什么选择某条记忆、模型最后是否使用了它，以及新增复杂度是否真的改善了玩家体验。

研究也让我意识到，模型辅助方案并不会消除设计工作，而是把工作从编写规则转移到了评分标准、缓存、验证样本和失败处理上。多种设计方案应先通过项目自己的查询与记忆测试确认收益。

目前实验规模较小，Boss 战和玩家历史也较短，图形负载还提高了参与门槛。后续我会优先考虑更轻量的客户端、更长但可控的共同历史、独立标注者、更大的参与者样本，以及跨模型测试，从而更清楚地区分检索策略、生成模型和实际游玩行为各自带来的影响。
